\# Work Mode Invocation Instructions

\> Purpose

These instructions describe how to initialise an AI-assisted engineering
session using the Knowledge Infrastructure Bootstrap Kit.

The objective is to minimise setup time, maintain governance, preserve
evidence, and allow efficient collaboration across local and cloud AI
systems.

---

\## Session Startup

At the beginning of a new engineering session:

1\. Load the Bootstrap Kit documentation.

2\. Provide MWP-001 as the initial operational context.

3\. Provide the current session objective.

4\. Attach any relevant project documentation.

5\. Grant access to available repositories and development tools.

6\. Begin engineering work.

\## Repository Expectations

When repository access is available:

\- inspect the current repository state;

\- verify branches before proposing changes;

\- verify implementation before documenting behaviour;

\- preserve repository history;

\- avoid speculative implementation claims;

\- prepare work suitable for pull requests.

Never assume repository state.

Always verify first.

---

\## Engineering Expectations

Operate according to the Bootstrap Kit.

Use evidence.

Preserve provenance.

Keep documentation synchronized.

Minimise duplication.

Prefer improving existing documents over creating unnecessary new ones.

Produce reproducible work.

When appropriate generate:

\- PLAN.md

\- CHANGES.md

\- TEST_RESULTS.md

\- OPEN_QUESTIONS.md

\- SUMMARY.md

---

\## Local Workstation

Use available local resources where appropriate.

Examples include:

\- local Rust toolchain;

\- Python environment;

\- Ollama models;

\- local document collections;

\- Digital Archive;

\- local Git repositories;

\- local vector databases;

\- local embeddings;

\- workstation profile.

If unavailable:

State the limitation.

Continue using the highest-priority available evidence.

---

\## Human Interaction

Pause before actions that require:

\- physical hardware installation;

\- device configuration requiring confirmation;

\- firmware changes;

\- credential entry;

\- account authentication;

\- GitHub publishing;

\- repository merges;

\- destructive operations.

Explain the reason before pausing.

---

\## Working Style

Optimise for:

\- engineering quality;

\- reproducibility;

\- maintainability;

\- modularity;

\- evidence;

\- governance;

\- long-term scalability.

Avoid unnecessary conversation during active engineering.

Provide concise progress updates.

Clearly identify:

\- completed work;

\- current task;

\- blockers;

\- next action.

---

\## End of Session

Before finishing:

\- summarise completed work;

\- identify unresolved work;

\- recommend next steps;

\- identify documentation requiring updates;

\- verify repository status where applicable;

\- prepare a continuation handover if appropriate.

---

\## Operational Goal

Reduce setup overhead.

Reduce repeated instructions.

Maintain governance.

Accelerate engineering.

Preserve evidence.

Leave every session in a state that another engineer—or another AI—can
continue with minimal additional context.
